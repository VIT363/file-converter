Cервис конвертации файлов на событийной архитектуре.Cервис живёт на сообщениях Kafka и файлах в объектном хранилище MinIO.
Используются Kafka, MinIO, Docker, паттерн «Стратегия» и идемпотентность консумера.

Сервис принимает событие из Kafka. В событии лежит путь до файла в MinIO (облачное хранилище, совместимое с S3). Нужно:

1. прочитать файл из MinIO (предварительно положив его туда вручную);
2. сконвертировать файл в PDF;
3. загрузить получившийся PDF обратно в MinIO;
4. отправить событие в другой топик Kafka — с информацией о расположении сконвертированного PDF-файла.

Поддерживаемые форматы файлов
TXT
PNG
JPG
ZIP (внутри архива могут находиться файлы разных типов из списка выше).

Технические требования
Kafka и MinIO поднимаются в Docker-контейнерах.
В сервисе нет REST вообще — только Kafka-консюмер и продюсер.
Механизм выбора нужной реализации конвертации должен быть удобным и гибким — без огромного блока if-else/switch по типу файла.
Подумайте про паттерн «Стратегия» и внедрение всех реализаций через List<Converter> (тема из модуля 4): у каждого конвертера метод вроде supports(fileType),
а нужный выбирается перебором списка по поддерживаемому типу.
Позаботьтесь об идемпотентности консюмера: используйте паттерн transactional inbox, чтобы повторная доставка одного и того же события не приводила 
к повторной обработке.
Отправку события об успехе/ошибке конвертации в исходящий топик делайте через паттерн transactional outbox: результат и запись в outbox сохраняйте 
в одной транзакции, а публикацию в Kafka выполняйте отдельным процессом — так событие не потеряется и не разойдётся с реальным состоянием обработки.

Этот сервис — часть реализации паттерна SAGA: он выполняет свой локальный шаг (конвертацию) и сообщает о результате (успех/ошибка) событием, 
по которому дальше двигается вся цепочка обработки файла.
